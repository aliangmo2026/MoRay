# MoRay 技术白皮书：本地 AI Agent 的安全与可复现性

## 一、为什么本地 AI Agent 需要七层路径防护

当我们让大模型操作文件系统时，最核心的风险不是"模型会不会犯错"，而是"模型犯错的代价有多大"。

一个未经约束的 AI Agent，如果被诱导执行 `rm -rf /` 或读取 `../../windows/system32/config/SAM`，后果是灾难性的。即使模型本身"听话"，prompt injection（提示注入）也可能通过被读取的文件内容篡改模型的后续行为——这就是著名的"间接提示注入"攻击。

MoRay 的七层路径防护，本质上是在"模型的决策"和"操作系统的执行"之间，建立一道**不可绕过的安全边界**：

1. **工作区根锁定**：所有路径强制解析到 `D:\MoRayWorkspace` 内，绝对路径和 `..` 越界在进入执行逻辑前就被拒绝。这意味着模型"想"读 C 盘的文件，但安全层根本不会让请求到达文件系统。

2. **符号链接逃逸拦截**：攻击者可能在工作区内创建一个指向 `C:\Windows` 的符号链接，诱导模型"读取工作区内的文件"。MoRay 用 `Path.resolve()` 解析真实路径，再做前缀判定，符号链接无法绕过。

3. **危险后缀拒绝**：即使模型被诱导"写一个文件"，`.exe` / `.bat` / `.ps1` 等可执行后缀也会被拦截，防止 Agent 被用来投放恶意程序。

4. **命令白名单**：`run_command` 不是"任意 shell"，而是只允许 `git status/log/diff/branch`、`python --version` 等只读命令。无 shell、无管道、无重定向——即使参数被注入 `; rm -rf /`，也会被当作非法字符拒绝。

5. **副作用人工审批**：写文件、移动文件、执行命令等有副作用的操作，必须经过人工确认，并展示 unified diff 红绿对比。这把"模型决定"和"人类确认"分开，人类是最终的安全闸门。

6. **全量审计落库**：每次工具调用——包括被拒绝的——都记录时间、参数、审批状态、耗时。这不是为了"追责"，而是为了**可观测性**：出了问题，你能回溯 Agent 到底做了什么。

7. **Windows 保留设备名拦截**：`CON` / `NUL` / `COM1` 等特殊设备名在 Windows 上可能导致意外行为，一律拒绝。

这七层防护的核心设计哲学是：**不信任模型的任何输出，只信任经过安全层校验后的执行请求**。模型可以"建议"任何操作，但安全层决定"允许还是拒绝"。

## 二、确定性回放对 AI Agent 有多重要

传统的 AI Agent 是"一次性"的：你发一个任务，Agent 执行，结果出来了。如果中间某一步失败了——比如读了一个不存在的文件、网络超时、参数写错了——你只能"重新来一遍"，而无法精确地回到失败的那一步。

这在调试和生产环境中都是巨大的痛点：

- **调试成本高**：Agent 跑了 10 步，第 7 步失败了。你想测试"如果第 7 步的参数改一下会不会成功"，只能从头跑 10 步，浪费时间和 token。
- **结果不可复现**：同样的输入，Agent 可能因为模型的随机性产生不同的执行路径。出了问题，你无法"复现现场"。
- **操作链断裂**：Agent 的每一步操作都是独立的，没有统一的事件记录。你无法回答"这个文件是什么时候、被哪一步、以什么参数修改的"。

MoRay 的确定性回放（Event Sourcing）解决了这些问题：

**事件快照**：每次工具调用的完整入参、出参、上下文状态都被序列化为不可变的事件快照，存入 `event_snapshots` 表。这类似于数据库的 WAL（Write-Ahead Log）——每一步操作都有完整记录。

**时间轴 UI**：「飞行记录仪」把所有工具调用可视化为时间轴，带状态颜色和可展开详情。你一眼就能看到"哪一步成功了、哪一步失败了、哪一步在等审批"。

**修改并重跑**：对失败的步骤，你可以直接修改参数（比如把错误的文件路径改成正确的），然后一键重放。重放不是"绕过安全直接执行"，而是**经过完整的七层路径防护和审批逻辑**——安全标准不变。

**审计可追溯**：重放产生新的审计记录，原始记录保留。完整的操作链可追溯："原始调用失败 → 修改参数 → 重放成功"，每一步都有时间戳和参数记录。

确定性回放的核心价值是：**把 AI Agent 从"黑盒一次性执行"变成"白盒可复现的工程系统"**。这是 AI Agent 从"玩具"走向"生产工具"的关键一步。

## 三、MCP 兼容：让安全能力被外部复用

MoRay 的七层防护和确定性回放，最初只服务于 MoRay 自己的前端。但通过 MCP（Model Context Protocol）兼容，这些安全能力可以被任何支持 MCP 的 AI 客户端复用——Claude Desktop、Cursor、Cherry Studio 都能通过标准协议安全地调用你的本机工具。

关键设计是：**MCP 调用与前端调用共用同一个执行入口**，七层防护、审批逻辑、审计日志完全一致。外部客户端不会因为"走了另一条路"而获得更宽松的权限。默认状态下，外部客户端只能调用 6 个只读工具；5 个副作用工具需要显式配置白名单才能放行。

这意味着：你在 MoRay 里建立的安全边界，可以延伸到任何你使用的 AI 工具中，而不需要为每个客户端单独配置安全策略。
