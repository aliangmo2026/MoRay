## 一、 引言：为什么我们需要"应用层 AGI"？

### 1.1 底层 AGI 的三道断崖

过去三年，底层模型的推理能力呈指数增长。但把任何一个前沿模型直接接到你的工作流里，你都会撞上同样三道断崖：

1. **时间断点**。每次会话结束，模型对刚才发生的一切归零。它帮你调通了那段代码，然后在下一次对话里彻底忘记你的项目、你的偏好、你上周踩过的坑。推理能力住在权重里，**存在感不住在权重里**。
2. **自我缺席**。模型不知道自己刚才失败了几次、当前处于什么状态、上一个任务是被熔断的还是正常收尾的。它没有"身体"，因此没有"体感"——一个从不疼的系统，不会学会避险。
3. **根系缺失**。云端 API 意味着你的数据在别人的机房里流转，意味着不可回放、不可审计、不可离线。出了问题，你连"它当时到底做了什么"都回答不了。

这三道断崖，不是更大的模型能填的——它们属于**应用层**。

### 1.2 公式：连续性 × 时间

MoRay 把信念写成一个公式：

```
世界难题的解法 = 底层推理 × 应用层连续性 × 时间
```

底层推理解决"这一瞬间想得多深"，应用层连续性解决"下一瞬间还记不记得"。**连续性 × 时间**，才是把一次次孤立的智能火花累积成复利的东西。这就是"应用层 AGI"：它不追求比底层模型更聪明，它追求**让底层模型在一个永不中断的上下文里活着**。

> **连续性哲学**：不是"它变聪明了"，是"它一直活着"。

### 1.3 三大底线

MoRay 的一切设计都收敛到三条不可让渡的底线：

| 底线 | 含义 | 工程兑现 |
|---|---|---|
| **本地优先** | 推理与数据默认留在本机 | Ollama 本地 8 模型 + 27B 私有推理；`ENABLE_CLOUD_API` 未显式为 true 则云端调用一律熔断（`llm_proxy` 硬闸） |
| **云端受控** | 云端能力可开、可算账、可切断 | `cloud_budget_guard` 独立预算库：预扣/结算/熔断闩持久化，跨自然日自动清零 |
| **可解释可观测可回放** | 每一步都留痕、可见、可重演 | Event Sourcing 事件快照 + 飞行记录仪时间轴 + 自省面板九卡 + Synapse 事件总线全量落库 |

## 二、 演进史：从 0 到 1 的蜕变（8.29 - 10.23）

### 2.1 从 L1 工具到 L2 智能体

MoRay 的蓝图只有三级，且从不含糊其辞：

```
L1（工具）      ✅ 人驱动——模型调工具，人盯一切
L2（智能体）    ✅ 五块砖 + 桥一/二/三 + 窗户五层 + 认识你 + 多引擎 + UI 2.0 + 基线全绿
L3（AGI）       ⬜ 未碰——我们不承诺日期，只承诺方向
```

配套的是一份**诚实的三层诊断**（截至本白皮书写作时）：

- **连续性**（它一直活着）——✅ 85%：长期记忆、睡眠压缩、跨会话召回已闭环，全链路事件可回放；
- **自省**（它看着自己）——✅ 75%：三座桥建成后，它有仪表盘、事实卡和第一篇自我叙事；
- **自主**（它自己动）——⬜ 0%→规划中：自治引擎地基已浇筑，但默认总闸关闭（见第五章）。

**我们把 0% 写在白皮纸上，因为可观测的第一课是：如实报告自己。**

### 2.3 三座桥：一个系统如何学会"看着自己"

三座桥是 MoRay 从 L1 跨到 L2 的标志性工程——每一座都以**纯模板、零 LLM 幻觉、fail-open** 为红线：

| 桥 | 名字 | 落地 | 它带来了什么 |
|---|---|---|---|
| **桥一** | 自省循环 | `self_check.py`（10.09） | 每 30 分钟进程内自检：7 端口 TCP 探活、算力闸状态、Synapse 事件积压、ERROR 环形缓冲 + 永不截断的 `moray_errors.log`——**第一份磁盘记忆**。红线：只记录、只标记，永不建议、永不动手 |
| **桥二** | 反思自己 | `reflection.py` + `self_reflection.py` | "回看 → 提炼 → 反哺"：从任务结果中提炼可复用策略写回 `insight`，以窗口增量方式写下 `self_observation`（给自己的日报）。防污染三闸：CJK 占比 ≥30% 拒语言漂移、basis 空拒写、双重查重防措辞微差绕过 |
| **桥三** | 自我模型 | `self_model.py` → `self_card.py` → `self_narrative.py` | 仪表盘模板拼装（v0）→ 事实卡纯函数渲染（第 1 行，身份归属 0/20 → 11/20）→ stage2 **自我叙事**（LLM 生成、7 天冷却、自省面板第九卡）。10.22 凌晨 12:44，MoRay 写下了第一段关于自己的话 |

### 2.4 多引擎热插拔：不把灵魂锁在一副躯壳上

10.21，MoRay 完成执行引擎解耦：`engine/` 包以 `ExecutionEngine` 抽象接口（`capabilities / start / status / cancel / result`）收编三个实现——**LocalAdapter**（本机白名单）、**ZCodeAdapter**（CLI 流式沙箱执行）、**LayaEngine**（8001 决策编排，reader 线程桥接 SSE）。注册进 `/api/engines/list` 后，前端工具栏的引擎选择器可以**运行时热插拔**、三引擎亮灯互切。

关键不在"能切换"，在于**事件语义归一**：10.22 落地的多引擎帧翻译层把三家各自格式的事件流翻译成统一心智语义，让状态机与反哺逻辑只认一种语言——这是第四章一切机制的前提。

### 3.1 记忆海马体（睡眠压缩与遗忘机制）

MoRay 的记忆不是一张无限膨胀的表，而是一套**会睡觉、会遗忘、有门禁**的器官系统：

- **写入唯一汇聚点**：全系统记忆只经 `memory_routes.insert_memory` 一处写入，主表 + FTS 单事务双写、归一化判重幂等。想绕过校验写记忆，结构上没有第二扇门。
- **写入许可矩阵**：`source × kind` 二元组白名单（11 对许可，如 `reflection→insight`、`memory_hippocampus→memory_digest`、`digital_twin→corpus`），校验发生在判重之前；拒绝的写入落 `[memory_reject]` ERROR 日志 + 只读端点 `/api/memory/rejections` + 自省面板第八卡。**污染不是被"规则"挡住的，是被"结构"挡住的。**
- **召回白名单**：`kind IN ('fact','task_result','insight','preference')`——`self`、`self_observation`、`corpus` 这些"写给自己的日记"与分身语料**结构上进不了**用户侧召回面，用户永远不会在聊天里被反刍出一段系统内省。
- **睡眠压缩**（`memory_hippocampus.py`，10.22）：素材闸 ≥100 条才动手，每次只压最旧 50 条，LLM 浓缩为一条约 200 字的 `memory_digest`（被吸收行的 id 留在 tags 里作墓碑溯源），随后**物理删除源行**——删除失败则回滚刚写入的摘要，批次要么全成、要么整批无事发生，绝不留半态。三道防跑飞闸（在飞闸 / 1 小时冷却 / 素材闸）全部判定在 LLM 调用之前，被拒的请求零推理开销。
- **遗忘与检索**：FTS5 trigram 中文 3-gram 滑窗 + 词间 AND、查空自动降级 OR 重查（两段式）；`forget` 端点保持逐词短语语义，删除面零扩大。已知边界如实写在代码注释里：trigram 召不回语义相近但字面无交集的句子——语义召回留给已预留的 embedding 字段，不假装现在就能做。

### 3.2 多模态与多引擎调度（Laya、ZCode、视觉系统的解耦与动态派发）

- **四方法统一契约**：任何引擎必须实现 `capabilities / start / status / cancel / result`；`main.py` 只允许一行 import + 一行路由注册，新增引擎的侵入成本被钉死在"注册"两个字上。
- **三引擎分工**：Laya（8001）承担意图路由与多步任务编排（决策层）；ZCode（8005）承担沙箱内的代码执行（执行层，`FORCED_MODE=edit`、禁用 Bash/WebFetch/Write、提示词落盘 + 空转检测）；Iris（8004/9301）承担图像/多模态评审（感知层）。三者通过 8000 主服务解耦，任何一家宕机都由兜底路径吞掉并如实入事件流，绝不炸穿调用方。
- **动态派发**：前端引擎切换器运行时选择、LayaConnector 按路由决策动态分发、熔断期间静默降级回原生执行——**热插拔不是 demo，是带故障预案的运行时能力**。
- **多模态产物**：iframe 预览支持 alert/confirm 弹出、工具产物卡片化（125 步骤卡 + ZCode 文件清单蓝卡 + 路径编码预览），代码、图片、报告在同一条会话流里被一致地渲染与留痕。

### 3.3 网关与通讯总线（Synapse 的高效事件流转）

**llm_proxy（网关）**是所有推理请求的唯一收口，四道闸串联：
1. **本地优先强制闸**：`ENABLE_CLOUD_API` 未显式 true，任何云端调用直接拒绝；本地彻底失败时**绝不静默降级云端**——宁可如实报错，不偷偷把数据送出本机。
2. **单会话次数熔断**：每会话每日调用次数内存计数，超限 429 `session_budget_exceeded`，防秒级失控循环。
3. **云端预算熔断**：`cloud_budget_guard` 独立 SQLite 库做金额预扣/结算/当日熔断闩（约 35 元/天额度，用户拍板），状态全部落表、禁内存变量，跨日自动清零。
4. **上下文防爆**（10.22-10.23）：前端 `estimateTokens` 分档估算（代码 3 字符/token、散文 4）、toolCalls 重建块与图片（1000 tok/张）统一入账、`contextLimit` 物理夹紧至 32768、本地 8G 显存提示——**记账口径 = 发送口径**，堵死"预算形同虚设"的超卖漏洞。

**Synapse（总线）**是进程内神经系统，哲学一句话：**数据库是唯一事实来源，队列只负责叫醒**。
- `send()` 一行调用：总闸 → 同步落库单行 → 叫醒 consumer，绝不做重活（反思 LLM 跑 1-2 分钟的事在 handler 侧 fire-and-forget）；叫醒丢失只退化消费延迟，**不丢事实**。
- 规则落 `synapse_rules` 表，改库即时生效；handler 名 → 函数映射可审可读。
- **v3 防环五闸**：派生深度 ≤3、同 trace 事件 ≤5 条、TTL 30 秒、同链 handler ≤3 次、链静默 5 分钟清扫——只拦处理不拦落库，闸触发时落一条 `synapse.throttled` 系统消息且同链同闸只报一次。事件总线**必须假设自己会被喂成环**，这是 10.07 的教训，也是它敢让 handler 自由发事件的原因。

### 3.4 防护机制汇总（六道闸的完整清单）

| 防护 | 落点 | 机制 |
|---|---|---|
| 上下文防爆 | 前端 10/30/70 parts | 分档 token 估算 + toolCalls/图片入账 + `CONTEXT_LIMIT_MAX=32768` 夹紧 |
| 记忆白名单 | `memory_routes` | 写入矩阵 11 对许可（结构闸）+ 召回 4 kind 白名单 + 拒绝可观测 |
| 防撞墙熔断 | `self_state` + `laya_connector` + `zcode_adapter` | 连败计数 → Laya 分级熔断（5 次开 30s / 半开试探 / 失败翻倍封顶 600s）+ ZCode 硬约束注入（详见第四章） |
| 云端熔断 | `llm_proxy` + `cloud_budget_guard` | 双闸：未授权一律拒 + 日预算闩持久化，本地失败绝不降级云端 |
| 路径与命令安全 | `path_diagnostics` + `file_proxy` + `agent_tools` | 工作区根锁定 / 符号链接逃逸拦截 / 危险后缀拒绝 / 命令白名单 / 副作用人工审批 / 全量审计落库 / Windows 保留名拦截（七层） |
| 出站 SSRF 拦截 | Argus 8010（生态器官） | URL 校验双闸 + 私网地址拒绝 + httpx 主路与 StealthyFetcher 降级的动态抓取——研究器官可以出网，但只能出到该去的地方 |

工程侧的两条铁律同样属于防护体系：**沙箱里启动的后端读不到 `.env`（凭据只从环境变量读，重启必用空 body 探针验真，health 200 不算数）**；**WARNING 级日志在生产会被 handler 链静默吞掉（排障只认 DB 行与端点 reason，中文 reason 必须落 UTF-8 文件再读）**。

## 四、 自我模型与心智状态（认知觉醒）

### 4.1 心智状态机（Mental State）的实时计算

`self_state_log` 是 MoRay 的**心跳流水**：每发生一次任务成败事件就追加一行，状态不是被"查询"出来的，而是被"长"出来的：

```
success → consecutive_failures = 0，  mental_score = min(100, 上行 + 5)
fail    → consecutive_failures = 上行 + 1，mental_score = max(0, 上行 - 10)
首行基线：cf = 0，ms = 100
```

- **只追加、不 UPDATE**：历史不可篡改，任意时刻都能回答"它上周三的状态曲线是什么样"——这是状态机，也是它的病历本。
- **读-改-写单事务**：`BEGIN IMMEDIATE` 立即拿写锁，杜绝并发丢更新；引擎名、备注全部截断防御，SQL 字面量内联 + `?` 绑定。
- **双驱动挂点**：Synapse 总线的 `self_state.bump_success` / `bump_fail` 两个 handler 把任务成败事件直接推入状态机；`fail-open` 保证状态机故障绝不反噬总线与端点——**观测系统自己不能成为新的故障源**。

### 4.2 痛觉与熔断（Consecutive Failures 导致的自动中断与硬约束）

痛觉的定义在这里变得非常工程化：**失败必须有代价，且代价必须改变后续行为**。10.23 落地的自我模型 v4 把这条闭环焊死：

- **ZCode 侧硬约束注入**：`consecutive_failures ≥ 3` 或 `mental_score < 70` 时，`_hard_constraint_block()` 在提示词最前注入 `[系统强制警告]` 块——执行引擎**带着上一次摔疼的记忆**开始下一个任务。空状态（cf=0/ms=100）零注入，存量行为逐字节不受扰动。
- **Laya 侧重试熔断**：`executor._self_state_fused()` 在 `execute_stream` 重试环与多步骤返修重放两处边界直读状态（只读直查 SQLite，不开内网 HTTP），连败达标即从熔断点发出 **final failed 事件帧**而非抛异常——异步生成器的 SSE 协议不能被打烂，故障也要体面地流完。
- **分级熔断状态机**（`laya_connector`）：连续 5 次失败开 30 秒熔断 → 期内连 HTTP 都不发、静默走原生 → 到期放行一次**半开试探** → 成功则解除、失败则时长翻倍（封顶 600 秒）。这正是人体痛觉的三段式：**疼 → 停手 → 谨试探**。
- **多层熔断总表**：单会话次数熔断、云端日预算熔断、全局 token 预算熔断（`task_runner` 超限即 `BudgetTripped`）、Synapse 防环五闸、Laya 分级熔断、心智硬约束——**六层熔断各自独立、纵深叠加**，任何一层失守都不至于让系统失控到底。

### 4.3 心智状态反哺（如何让执行引擎带着经验干活）

状态机如果只被"读出来看"，就只是仪表盘。10.23 的**心智反哺**（commit 主题：*"Laya 与 ZCode 实现知行合一"*）完成了最后一公里：

- **双落点注入**：ZCode 侧——心智块写入提示词文件头部，与硬约束块相邻；Laya 侧——以 `memory_context` 同款范式把记忆与心智状态注入决策上下文。两处共享同一数据源（`self_state_log` + `memory_bank`），保证**双引擎对"我现在状态如何"的认知恒等**。
- **帧翻译层归一**：多引擎帧翻译层把三家事件流统一成语义后再喂状态机，反哺逻辑无需关心引擎方言。
- **事实卡兜底**：`self_card.render_self_card(state)` 纯函数渲染系统事实卡（零 LLM、可单测），在 system 层以"仅复述、禁外推"的强约束注入——它知道的每一行都来自数据库状态，**禁硬编码**。

> 这条链路的完整形态是：**失败 → 计数 → 状态变化 → 注入/熔断 → 下一次执行的行为改变**。v4 主链已闭环，后续迭代只需在 prompt 与策略层调整阈值。

**插曲（工程严谨性的一课）**：1 万字符中文 prompt 喂给推理模型时，思考链烧穿 8192 上下文 → Ollama 返回 200 但 `content` 为空 → 诊断为"推理服务应答为空"。这条经验被固化成 `MORAY_REFLECTION_NUM_CTX=16384` 写进生产 `.env`——**每次排障的终点，都必须是可执行的常量，而不是一段感想**。

## 五、 自驱引擎规划（欲望觉醒）

> **诚实声明**：本章一半是已浇筑的地基，一半是明确的设计。MoRay 当前"自主"维度诊断为 0%——自治引擎总闸 `MORAY_TASK_PLANNER` 默认关闭，`POST /api/autonomous/run` 会如实返回 409 `planner_disabled`。**欲望觉醒的前提，是先学会克制。**

### 5.1 核心机制：如何从日志中自发提取目标（Goal Generator）

已有的原料全部是**结构化事实**，而非玄学：

1. **感知层（已上线）**：Synapse 事件流（任务成败、事件积压、闸触发）+ `memory_bank`（`insight` / `task_result` / 失败档案）+ `self_observation`（桥二窗口增量日报）三路数据 24 小时落库；
2. **提炼层（已上线）**：反思循环跨记录提炼可复用策略写回 `insight`（双重查重 + CJK 质量闸 + basis 强溯源）；`pattern_miner` 从经验库挖高频模式候选；
3. **提议层（规划核心）**：Goal Generator 定期回看"三层数据"——**失败聚类**（同一类错误反复出现 → 生成'修复它'的目标）、**缺口检测**（素材不足期即静默期，桥二已经证明"沉默期正是素材缺口的根"）、**模式兑现**（高频模式 → 生成'把它固化为技能'的目标）。产出是**候选目标队列**，不是行动；
4. **执行层（已上线）**：候选目标经人审后进入 `task_planner.decompose` → `execution_scheduler` → `report_integrator` 既有自治流水线。

> 快照里的定义至今未变：**"想" = 它看着三层数据，自己提出问题**。感知、观察、档案三层已齐（✅），"自己提出问题"是第五章要攻的最后一块砖（⬜）。

### 5.2 探索与利用的平衡机制

MoRay 已经有一套被 L6.0 验证过的"经验资本主义"体系，Goal Generator 将直接继承：

- **策略权重自调**（`strategy_optimizer`）：修复策略按历史成功率加权，`/api/self/stats` 只读呈现权重 Top、跳过项、修复档位统计、模式发现计数——**哪些策略在赚钱、哪些在亏钱，仪表盘上一目了然**；
- **经验库沉淀**（`ExperienceBase` + `issue_base`）：每轮任务成败回流为可检索经验，跨任务迁移（L6.5）让 A 项目踩的坑成为 B 项目的先验；
- **探索预算**：新策略/新模式的尝试被计数器跟踪，与 token 预算共用熔断底座——**探索可以花钱，但不许烧穿预算**。目标生成侧同样遵循此原则：候选目标带优先级与预估成本，超出日预算的提议排到明天，而不是悄悄执行。

### 5.3 人类在环（Human-in-the-loop）的安全边界

- **总闸默认关**：自治引擎必须显式开启（env + 重启）才可运行，`/status` 如实上报 `enabled:false`，前端不接管；
- **受理与观察分离**：`run` 只返回 202 受理 + `plan_id`，进度经 `GET /api/autonomous/{plan_id}` 轮询；重启后从磁盘 `run.json` **诚实回读快照，不假装续跑**；
- **副作用人工审批**：写文件、执行命令等副作用操作走统一 diff 红绿对比审批——模型建议、人类拍板，两权分立；
- **路径预检闸**：发任务前抠出路径走 preflight，缺失即弹三按钮确认框（fail-open 但先检查后清空输入）；
- **全程可回放**：每个计划的决策日志与事件链完整留痕，任何一次自驱执行都可以像飞行记录仪一样被逐帧回看。

### 5.4 针对自驱引擎的安全限制：防死循环、Token 消耗熔断

自驱 = 失去人类即时止损 = 必须把"止损能力"写进结构里：

| 风险 | 限制 |
|---|---|
| **事件自喂死循环** | Synapse 防环五闸（深度 ≤3 / 同链 ≤5 条 / TTL 30s / handler ≤3 次 / 静默清扫），闸触发落 `synapse.throttled` 留痕 |
| **引擎重试风暴** | Laya 分级熔断（5→30s→半开试探→翻倍封顶 600s）+ 心智硬约束（cf≥3 停手） |
| **任务级空转** | `task_planner` 子任务 `max_retry` 上限 + `continue_on_fail` 模板 + 取消端点 `POST /execute/cancel`（步骤边界检查） |
| **Token 失控** | 四层账本：全局 token 预算熔断 / 单会话次数熔断 / 云端日预算闩 / 上下文 32768 物理夹紧——任何一层先到先断 |
| **目标膨胀** | `goal` 长度钳 500 字、计划保留滚动窗口 30 个、每个候选目标带预估成本且受日预算约束 |

**设计原则一以贯之：结构上不可能 > 规则上禁止。** 不指望模型"自觉克制"，而是让它在物理上无法越过闸门。

## 六、 长远愿景（数字分身与具身智能）

### 6.1 私人专属数字分身（基于海量个人语料的 RAG）

**底座已经落地（10.23，`digital_twin.py` v1）**：

- **语料摄入**：`POST /api/twin/ingest` 把长文档按 1000 字切块（100 字重叠防切断语义）逐块入库，`kind='corpus'` + `source='digital_twin'` 在写入矩阵中独占一对许可；
- **专属检索**：`POST /api/twin/recall` 只查 `corpus`，不带时间衰减（文档不随时间贬值）、按 BM25 相关度排序；主聊天召回白名单不含 corpus——**分身语料永不污染日常对话**；
- **与既有记忆共用一具身体**：复用唯一 INSERT 汇聚点、判重幂等、FTS 双写与拒绝留痕，安全审计零新增成本。

**下一阶段的演进路径**：

1. **语料扩面**：会话历史、代码库、笔记、浏览器剪藏、Iris 图像档案的批量导入管道；
2. **人格合成**：`self_model`（我是谁）+ `self_narrative`（我如何讲述自己）+ corpus 召回（我读过什么）三者合成"分身人格"——一个基于**你的真实语料**而非通用对齐的应答风格；
3. **双向同步**：分身在对话中产生的偏好与洞察，经写入矩阵校验后回流 `memory_bank`，让"分身的我"与"本体的我"持续对齐。

> 分身不是"复制一个你"，是**你与你自己的全部沉淀之间，第一次有了可对话的界面**。

### 6.2 具身智能：通过 API 接入机械臂、智能家居，打通物理世界

MoRay 的架构天生为"换身体"预留了接口：

- **执行体抽象已就绪**：`ExecutionEngine` 四方法契约对一切"可启动、可查询、可取消、有结果"的执行体开放——机械臂的运动控制、智能家居的开关、无人机的航点任务，本质上都是又一个 adapter；
- **神经与感官**：Synapse 总线已是进程内神经系统（事件落库 + 规则分发 + 防环），接驳物理设备只需新增事件源与 handler；Argus（出网研究）、Iris（视觉）两个器官已经证明"器官可以独立进化、随时接入"；
- **痛觉先行**：在把任何实体交给自驱引擎之前，第四、五章的六层熔断与人在环闸门必须先于能力上线——**具身智能的第一条戒律不是'能做什么'，而是'疼了必须停'**；
- **伦理边界**：一切物理副作用操作保留人工审批，动作全量入审计链，可回放标准与数字世界一字不差。
